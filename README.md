# Кореш для Telegram и Bothost

Бот: **@Poker_Empire_1_bot**. Владелец: **379721932**.
Приватный репозиторий: **https://github.com/kuzia45/koresh-bot**.
Рабочая папка: `C:\Users\kuzia\Desktop\projects\koresh-bot`.

Для запуска из GitHub следуйте [пошаговой инструкции Bothost](DEPLOY_BOTHOST.md).
Основная ветка — `main`. Bothost получает обновления из этой ветки по кнопке
«Обновить из Git» или автоматически после настройки webhook.

Рабочее имя персонажа — **Кореш**. Имя и обращения меняются через `BOT_NAME`
и `BOT_ALIASES`; username в Telegram бот определяет автоматически.

Это отдельный агент Codex с новой памятью вашей группы. Авторизация через
ChatGPT расходует лимиты имеющейся подписки. API-ключи бот не принимает и
не наследует из окружения. Текущая переписка в Codex автоматически в бота
не переносится.

## Что умеет

- Разговорный стиль, мат без цензуры по ситуации, без обязательной шутки в каждом ответе.
- Отвечать на имя, `@username`, реплай на своё сообщение и личку владельца.
- Иногда вступать сам: по умолчанию вероятность 4% на новое сообщение,
  минимум 10 минут между попытками; модель может решить промолчать.
- Искать в интернете через встроенный веб-поиск Codex.
- Видеть присланное фото или фото в реплае при прямом обращении.
- Читать TXT, MD, CSV, JSON, LOG, YAML, PY, DOCX до 8 МБ; в контекст попадают
  первые 20 000 символов. Код из присланных файлов не выполняется.
- Присылать созданные текстовые файлы TXT, MD, CSV, JSON.
- Самостоятельно находить готовые мемы в интернете и отправлять картинку,
  когда об этом просят обычными словами или когда это уместно по контексту.
  `/meme [тема]` делает тот же поиск без запроса к ИИ. Ручная копилка не нужна.
- Каждый день выбирать случайного «пидора дня» и вести статистику без ИИ.
  По умолчанию розыгрыш проходит в 12:00 по Москве.

Версия **2.0.1**. Подробности обновления, памяти и розыгрыша: [CHANGELOG.md](CHANGELOG.md).

PDF, голосовые, просмотр содержимого видео и генерация картинок в эту версию
не включены. Самостоятельные реплики зависят от поступления новых сообщений:
бот не пишет по таймеру в молчащую группу.

## Память и MD-файлы

Для каждого чата отдельно сохраняются:

| Данные | Где | Как долго |
|---|---|---|
| Последние сообщения | `/app/data/koresh.db` | До 7 дней, максимум 300 на чат |
| Контекст одного ответа | Последние 40 сообщений соответствующей ветки | Передаётся при запросе |
| Долгосрочная память | SQLite + `/app/data/chats/ID_ЧАТА/memory.md` | До `/forget` |
| Памятки `/remember` | SQLite и тот же `memory.md` | До `/forget`, максимум 30 |
| Недавно отправленные интернет-мемы | URL в SQLite | Последние 100 на чат, чтобы не повторять |
| Участники и результаты розыгрыша | SQLite | Между перезапусками и обновлениями |
| Авторизация Codex | `/app/data/codex` | До выхода из аккаунта/отзыва сессии |

В `memory.md` бот автоматически кратко записывает имена, предпочтения,
внутренние шутки и договорённости. Это происходит в том же запросе, что и
ответ: отдельный запрос на каждое входящее сообщение не нужен. Автоматическая
память ограничена 5000 символами. Модель может ошибаться; важные факты лучше
закреплять через `/remember`. Файл доступен владельцу через файловый
менеджер Bothost; команд для его выгрузки в чат нет. Источник истины — SQLite:
ручную правку MD бот перезапишет.

Группы не получают историю и мемы друг друга. Ветки Telegram имеют отдельный
краткий контекст и общую долгосрочную память своей группы. Перед добавлением
бота расскажите друзьям про память и `/privacy`: выбранные сообщения, память
и содержимое прикреплённых для анализа файлов передаются в OpenAI.

## Развёртывание на Bothost без Git

1. В профиле Bothost в разделе **Интерфейс** включить **Загрузка бота из архива**.
   На дашборде появится соответствующая кнопка. Нужен Базовый или Pro.
2. Загрузить архив `koresh-bot.zip` из комплекта. В его корне лежит `Dockerfile`.
3. Название в панели: **Кореш**. Платформа: Telegram. Токен: от
   **@Poker_Empire_1_bot** — вводится непосредственно в Bothost.
4. Использовать **свой Dockerfile**; главный файл — `bot.py`. Для запуска
   необходим установленный Codex CLI, поэтому стандартный Python-образ
   без нашего Dockerfile не подойдёт.
5. Владелец `OWNER_ID=379721932` уже задан в Dockerfile. В переменных можно
   изменить его и остальные параметры из `.env.example`. Bothost сам
   предоставляет `BOT_TOKEN` из поля токена.
6. Запустить деплой. При необходимости включить веб-интерфейс с внутренним
   портом `8080`. `/health` — только проверка процесса, без секретов и данных.
7. После успешного запуска написать боту в личку **`/login`**. Бот пришлёт
   официальную ссылку OpenAI и одноразовый код. Войти в аккаунт с подпиской.
   Проверка: **`/status`**.
8. В BotFather выбрать `/setprivacy` → этого бота → **Disable**, затем
   заново добавить бота в группу. Это нужно, чтобы он видел общий контекст
   и мог иногда включаться сам. Права администратора не требуются.
9. В группе от аккаунта владельца написать **`/allow@Poker_Empire_1_bot`**.
   Затем: **`Кореш, знакомься с бандой`**.

Если у этого Telegram-бота уже запущена другая программа, сначала остановить
её: два процесса с одним токеном будут конфликтовать. Деплой из архива у
Bothost пока привязан к тестовой ноде; доступность OpenAI из её региона
проверяется при реальном входе и первом запросе. Если нода недоступна, можно
использовать Git-деплой того же исходного кода и выбрать подходящий регион.

Обновление: загрузить новый архив через карточку бота. Папка `/app/data`
должна сохраняться, включая память и авторизацию. В Dockerfile программа
специально находится в `/opt/koresh`, потому что Bothost монтирует исходники
поверх `/app`.

## Настройки

Обязателен `BOT_TOKEN`. В Dockerfile уже заданы `OWNER_ID`, `DATA_DIR`,
`CODEX_HOME` и `PORT`. Остальные значения необязательны:

| Переменная | По умолчанию | Значение |
|---|---|---|
| `BOT_NAME` | Кореш | Имя персонажа |
| `BOT_ALIASES` | кореш,корешок | Обращения через запятую |
| `ALLOWED_CHAT_IDS` | Пусто | Группы через запятую; можно подключать `/allow` |
| `CODEX_MODEL` | Модель Codex по умолчанию | Модель, доступная подписке |
| `CODEX_REASONING_EFFORT` | low | Глубина рассуждения |
| `SPONTANEOUS_CHANCE` | 0.04 | Вероятность попытки самостоятельной реплики |
| `SPONTANEOUS_COOLDOWN` | 600 | Пауза между попытками, секунды |
| `MAX_TURNS_PER_HOUR` | 30 | Общий для бота предел попыток запроса за час |
| `CONTEXT_MESSAGES` | 40 | Сообщений в контексте |
| `HISTORY_DAYS` | 7 | Срок хранения короткой истории |
| `CODEX_TIMEOUT` | 150 | Таймаут запроса, секунды |
| `MAX_QUEUE` | 12 | Максимум заданий в очереди |
| `DAILY_DRAW_TIME` | 12:00 | Московское время ежедневного розыгрыша |

Выполняется один запрос Codex одновременно. Каждое обращение и каждая
выбранная попытка самостоятельной реплики расходуют лимит запросов; реальные
ограничения подписки действуют дополнительно. Старые сообщения после
долгого простоя не вызывают обычные ответы. Очередь заданий находится в
памяти процесса: при перезапуске незавершённый запрос нужно повторить.

## Если вход по коду не работает

Включить **Device code login** в настройках безопасности аккаунта ChatGPT
и повторить `/login`. Ссылка для ввода кода:
<https://auth.openai.com/codex/device>. Ссылка и код присылаются только владельцу
в личке; в историю, которую читает модель, они не записываются.

Если этот способ недоступен, из терминала Bothost можно выполнить:

```sh
codex login --device-auth
codex login status
python3 /opt/koresh/bot.py --check
```

При полном отсутствии device auth документация OpenAI описывает вход через
SSH-перенаправление или перенос кэша авторизации с личного компьютера.
Файл авторизации содержит токены: его не добавляют в исходники или архив.
Здесь такой перенос автоматически не выполняется.

## Устройство и проверки

Python 3.11+ и стандартная библиотека. Telegram Bot API используется через
HTTPS long polling, вебхуки при старте отключаются. При ошибке `409` нужно
остановить другую копию бота; при `401` проверить Telegram-токен.

Codex запускается через `codex exec` с авторизацией ChatGPT, фиксированной
JSON-схемой ответа, эфемерными сессиями и режимом `read-only`. Терминал,
выполнение кода, плагины и управление компьютером для модели отключены;
веб-поиск доступен через Code Mode host. Бот сам скачивает только выбранные
вложения Telegram и присылает текстовые результаты. Токены приложения не
наследуются дочерним процессом. Тексты переписки не пишутся в логи приложения.

Тесты:

```sh
python3 -m unittest discover -s tests -v
```

Проверено локально на Windows: маршрутизация сообщений, отдельная память
групп и веток, MD-экспорт, очистка памяти, ограничение частоты, права
владельца, мемы и защита путей выгружаемых файлов. Через установленный Codex
CLI `0.171.0-alpha.13.2` выполнены реальные запросы по подписке: реплика
персонажа, веб-поиск и обновление долгосрочной памяти. Dockerfile фиксирует
серверную версию Codex `0.172.0`; сам Docker-образ и запуск на Bothost
проверяются при деплое, локального Docker в рабочем окружении нет.
